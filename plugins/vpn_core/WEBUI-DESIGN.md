# VPN 页面配置流程研究

当前 `vpn_core` 已实现出口卡片、按类型显示的配置表单、多 Peer WG 配置、wg.conf 粘贴导入和独立核心管理。0.7.2 支持粘贴 SS / VMess / VLESS / Trojan / Hysteria2 / AnyTLS 链接及整体 Base64 内容，导入一组节点并选择其中一个，自动生成完整 Mihomo / sing-box 配置。直连网段、域名、DNS 和原生 JSON 位于可折叠高级栏；编辑仅读取名称、协议、所选序号和高级设置，凭据不回填。节点集合按出口保存在加密 Secret 内，重新粘贴整体替换，不是共享节点目录；切换仍需显式应用并重建连接。

WireGuard 地址使用填写或导入的值；Mihomo / sing-box 和外部 TUN 的内部 WAN 地址可留空，由后端避开本机网段、非默认路由、其他草稿和活动租约自动分配并固定。内部 WAN 地址覆盖、WG 监听端口和宿主内网路由只在对应类型的高级设置出现。高级出口 JSON 与加密核心 JSON 继续支持。**下文是后续完整订阅/目录方案**，涉及远程订阅获取、共享节点目录、自动上联选择和运行时切换的部分尚未实现。

## 页面与主流程

VPN 首页以“出口”为主，顶部提供“添加出口”，其次是“来源与节点”和“核心管理”。安装核心只在首次需要时提示，版本、路径、校验值放到核心管理的高级设置。

```text
添加出口
  ├─ 代理：导入订阅 / 粘贴分享链接 / 手工添加节点 / 导入核心配置
  │         → 预览可用节点 → 选择节点 → 选择实际上游 → 保存并应用
  └─ WireGuard：导入 wg.conf / 填写表单
            → 预览地址、对端和 AllowedIPs → 保存并应用

出口卡片 → 在 LAN / 出向 NAT 中分配 → 整个 LAN 或指定下游使用该出口
```

出口卡片显示名称、类型、当前节点或 WG 对端、实际上游、本机就绪状态及配置是否有未应用修改。操作是“选择节点”“编辑”“应用”“停用”。多 peer WG 显示 peer 列表和各自握手时间，避免将其中一个 peer 当作可任意切换的代理节点。

不要把进程运行或 TUN 就绪显示成“节点健康”。WG 握手时间、核心运行状态、主动探测结果分别标注；空闲 WG 的旧握手时间本身不代表断线。

## 三类数据

| 对象 | 用途 | 公开资源只保存 |
| --- | --- | --- |
| 来源 | 一份订阅、手工节点集合或导入文件 | 名称、类型、更新时间、修订号、更新结果、Secret 引用 |
| 节点 | 从来源解析出的可选代理 | 稳定 ID、名称、协议、兼容核心、来源 ID、凭据引用 |
| 出口 | 被 LAN / NAT 引用的稳定 WAN | 名称、driver、slot、选中节点 ID、上游、草稿/已应用修订号 |

订阅 URL（含路径、查询 token）、请求头、完整导入文本、节点密码、WG 私钥/PSK 都进入 Secret，不进入普通 resources、状态、错误或浏览器本地存储。名称与服务器摘要也可能敏感，仅在已授权管理页展示；列表不返回完整配置。

节点 ID 由来源和规范化连接配置生成的带密钥摘要标识，排除显示名，不能用节点名称或数组位置作为身份。同名不同节点可区分，改名保留关联；凭据或协议参数改变视为新版本，供用户确认。

一个来源可以被多个出口引用，导入订阅不会为每个节点启动一个核心。第一版沿用每个已应用出口一个受管理核心，最多受现有 8 个 slot 和资源限制约束。不同上游或 DNS 设置不应强行复用一个核心；后续共享核心需要先定义路由隔离、故障范围与资源计费。

## 导入与选择

### 代理

优先支持现有两核心的 JSON 配置及逐项明确支持的节点分享格式，随后支持 Mihomo YAML 订阅。应在导入界面展示支持矩阵，不能宣称通用订阅转换：Mihomo 和 sing-box 的节点、DNS、规则、证书和传输字段并不一一对应。

- 导入先预览节点数量、重复项、不兼容字段和所属核心，再保存草稿。
- 节点表支持名称/协议筛选，按来源分组，明确标记不兼容节点；先选节点，再根据兼容性自动推荐已安装核心。
- 第一版“固定节点出口”只提取已支持的节点配置，生成明确的最终出口，不静默沿用订阅中的 DIRECT、fallback 或负载均衡组。
- 完整核心配置作为独立高级模式，保留其规则语义；页面不能将规则组中的一个节点冒充为所有流量的实际出口。
- 引用证书、规则集、外部 provider 或相对路径时必须检查依赖，不支持的依赖明确列出，不能只导入主 JSON 就显示成功。
- 不上传订阅到第三方转换服务，不执行订阅中的命令或任意脚本。

更新订阅先完整下载、解析、校验，再原子发布新草稿修订。失败保留旧目录和已应用配置。选中节点消失时保留运行快照并提示“来源已移除该节点”；不自动切换其他节点或 DIRECT。更新和自动定时更新默认不重启出口。

第一版切换节点通过现有 apply 和进程管理完成，按钮明确提示该出口现有代理连接会中断。后续再按核心验证 selector API：通过受限宿主代理绑定受管理进程、出口和允许的操作，不把 controller 端口暴露给网络或浏览器，也不接受任意 API URL。现有 `net.http.request` 没有 Unix socket 参数，不能假设直接支持该方案。

### WireGuard

表单提供隧道地址、私钥状态、对端公钥、endpoint、AllowedIPs、PSK 和 keepalive，MTU/监听端口放入高级设置。支持多个 peer，按 AllowedIPs 选路的语义保持不变。

`wg.conf` 导入只接收声明式字段：Interface Address/PrivateKey/ListenPort/MTU 与 Peer PublicKey/PresharedKey/Endpoint/AllowedIPs/PersistentKeepalive。`PostUp/PreUp/PostDown/PreDown`、`SaveConfig`、`Table` 等必须列为不支持项并阻止直接应用，不执行或默默忽略。DNS 不属于当前 VPN profile，需提示交给 LAN DNS 配置处理。

当前 endpoint 只接受数值 IP；域名 endpoint 不能在 UI 中直接放行。支持域名需另补解析、TTL 更新、选路防递归与恢复测试。当前 WG 驱动也没有代理核心的 `upstream_interface` 绑定：若要统一展示“指定上游”，必须先补宿主选路实现；第一版应如实显示“按宿主路由”，不能只保存一个无效字段。

私钥和 PSK 导入后直接加密保存，重新编辑仅显示“已设置”，支持替换；不回填。WG 内网互联沿用现有能力边界：IPv4 出向 NAT 会改变下游源地址，远端主动连接下游需要额外转发，不能将该表单描述为完整双向 mesh。

## 自动填写与出口分配

普通模式只要求出口名称、来源/节点及实际上游。当前页面分配 profile key 和空闲 slot，后端校验活动 slot 冲突，并在首次应用时分配代理 WAN 的 `/32` 地址；地址检查已有草稿、active lease、本机接口网段和非默认路由，选定后固定在应用租约。WG 地址使用填写或导入值，不能随意生成。后续可将 key/slot 的草稿预留一并移到后端以改善多页面并发编辑。

上游选择器仅列出适用的物理、VLAN、PPPoE 等接口，并展示名称、地址和 WAN 名称；过滤本出口和其他 VPN 边界，后端继续校验，防止递归。未知或暂时掉线的已保存上游保留为不可用项，不能自动换成另一条出口。

应用成功后提供“去分配出口”，跳转 LAN / 出向 NAT 的现有编辑页并预选稳定 WAN ID。已有 WAN 选择逻辑负责填充接口、源地址和 prepared_l2；普通用户无需复制这三个字段。没有授权的跨插件资源写入能力时只提供跳转和摘要，不额外扩大插件写权限。提交时后端再次校验 WAN 可用性。

第一版不在 VPN 页另造设备规则引擎，复用现有 LAN 默认出口和下游 NAT 子集覆盖。编辑旧 JSON 配置时能识别的转表单，不可无损转换的继续高级模式，不自动重写正在运行的配置。

## 宿主与插件实现边界

现有 `resources`、`secret`、actions、持久 lease、进程管理和 `wan.adapter` 足以承载目录、表单和固定节点应用；不需要为订阅或节点增加逐包数据路径。

仍需实际实现的部分：

| 部分 | 建议实现 |
| --- | --- |
| 订阅获取 | 插件新增受控 `net.http` 权限及 endpoint policy，指定实际上游、TLS 校验、响应/解压大小、超时和重定向范围；在 worker 中下载，避免占用健康修复的控制回调 |
| 格式解析 | 现有 JSON 和有界 URI/Base64 解析可复用；YAML 当前没有现成 SDK 解析入口，应随包携带有界安全解析器或另做通用有界解析 API，不使用 shell 转换 |
| 目录与修订 | 新增来源、节点摘要资源及 Secret；导入、更新、选择和应用 action 分开，采用修订校验与幂等恢复 |
| 配置生成 | 复用已有分享节点到两核心的配置生成器，扩展协议矩阵；保留强制 TUN、禁止自动路由/redirect 和关闭额外控制端口的约束 |
| 出口向导 | 插件 UI 内完成；上游和 WAN 目录沿用宿主允许的只读信息，缺少字段时补通用 UI 数据能力 |
| DNS | 简单模式优先实际 IP 解析；DNS/fake-IP 必须与核心和 LAN 一起验证，不能假设宿主代发 DNS 会继承下游 WAN |
| 动态选节点 | 后续通用受限本地进程 API 能力及核心适配；未验证之前仍使用显式 apply |

订阅下载使用已可用的物理上游，避免“订阅要靠尚未配置完成的代理才能下载”的循环。若后续提供经代理更新，应单独验证、展示依赖和失败回退策略。取订阅和远程安装可执行插件是两种能力；订阅功能不应要求开启远程插件安装，也不改变现有 exec 策略。

## 分期与验收

1. 先做出口表单、WG 导入、单节点/现有核心 JSON 导入及来源摘要。验证空闲 slot 并发分配、密钥不回填、旧配置兼容和 LAN/NAT 分配。
2. 再做明确格式的订阅、筛选选择和修订更新。验证恶意 YAML/URI、响应超限、重定向/内网访问策略、同名节点、节点消失、更新失败、并发编辑和重启恢复。
3. 最后做逐核心运行时切换、主动节点探测和可选自动选择。验证旧连接处理、UDP、DNS/fake-IP、控制 API 访问范围，以及断链后不回退直连。

每一期都要保留普通 TC WAN 首次使用、VPN 创建/重启/删除和多出口并存的真实流量回归；UI 的“应用成功”仅在已发布 WAN 后返回，超时/部分失败保留草稿并给出可重试状态。
